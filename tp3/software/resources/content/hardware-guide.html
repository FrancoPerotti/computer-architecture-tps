Preparar el equipo y la Basys 3

La aplicación utiliza openFPGALoader 1.2.0 incluido. No necesitás instalar Vivado para programar el bitstream distribuido. Si falta el bitstream de TP3, la aplicación lo informa antes de intentar programar.

Conexión y selección

  1. Alimentá la placa y conectá su puerto USB de programación con un cable que transmita datos.
  2. Actualizá los destinos. JTAG programa la FPGA y UART transporta los comandos del procesador; son funciones distintas del mismo acceso USB.
  3. Con varios candidatos, seleccioná JTAG y UART correspondientes a la misma placa. Si desaparece un puerto recordado, elegí el destino explícitamente: no se sustituye por otro.
  4. Prepará la placa. El resultado distingue programación del bitstream y comprobación UART. Una programación confirmada permite reintentar la conexión sin volver a programar.

Linux: acceso USB y serie

Ejecutá la aplicación con tu cuenta habitual. Si aparece un fallo de permisos, pedí la preparación administrativa del dispositivo; la aplicación no modifica grupos ni reglas del sistema.

Para UART, revisá el propietario y grupo del puerto que se haya enumerado:

ls -l /dev/ttyUSBX
id

La letra X es el puerto real mostrado en la aplicación. El grupo y el procedimiento dependen de la distribución; puede ser necesario cerrar la sesión y volver a entrar después de un cambio de grupos.

Para USB/JTAG, una regla de acceso debe limitarse al dispositivo y a su número de serie real. Ejemplo para una sesión local que utilice systemd-logind, a revisar por el administrador:

SUBSYSTEM=="usb", ATTR{idVendor}=="0403", ATTR{idProduct}=="6010", ATTR{serial}=="SERIE_REAL", TAG+="uaccess"

No copies SERIE_REAL literalmente ni cambies permisos de todos los dispositivos USB. Tras instalar una regla administrativa se recarga udev y se reconecta el dispositivo. Conservá también el acceso UART; liberar JTAG no concede por sí mismo permisos sobre el puerto serie.

Windows: interfaces y controladores

La verificación Windows está pendiente. El binario nativo previsto utiliza libusb para JTAG y debe conservar la función VCP del puerto COM para UART. La elección del controlador y su interfaz se comprobarán con la placa real; cualquier cambio administrativo se realiza sobre la interfaz de programación identificada, preservando UART y las herramientas del laboratorio. No reemplaces indiscriminadamente ambas funciones USB.

Resultados y recuperación

CHECK_READY comprueba comunicación; no identifica el firmware instalado. Al iniciar una instancia nueva se requiere preparar explícitamente la placa. Si la programación se confirma y UART falla, revisá cable, permisos y selección antes de reintentar Conectar UART. Si un RESET queda sin confirmar, cerrar y reabrir el puerto no concede otro intento automático.

La prueba con Basys 3 real y la aceptación Windows continúan pendientes. Los ensayos locales con dispositivos controlados no acreditan programación física.
